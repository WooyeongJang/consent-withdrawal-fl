## 실험 A — L3 검정력과 판정 신뢰도

### A0. 기존 결과 재현(선행 조건)

- 입력: `results/final/e2/*.json` 190개.
- 원고의 규칙 서술만 보고 TOST와 양성 대조를 새로 구현한다(`fl/l3.py`를 import하지 않는다). 자기 참조 제외(U0 시드 1–5는 참조 4개)를 적용한다.
- 통과 기준: (a) 저장된 `L3.class`(원고 규칙 적용 뒤)와 100% 일치, (b) Table S10 첫 행(U0 145, U1 77, U2 66, U3 68, U4 3, U4s 11)을 그 표의 정의대로 재현. 일치하지 않으면 차이를 보고하고, 이후 분석은 다시 계산한 값을 쓴다는 점을 명시한다.

### A1. 기존 로그만 쓰는 분석

**분산 성분(관측)**, 시나리오 g마다:
- s_ref: U0 모델 10개(참조 5 + 시드 6–10)의 LiRA AUC 표준편차(자유도 9). 90% 구간은 χ²로 준다.
- se_boot: 대상 AUC의 부트스트랩 표준오차 = 95% CI 폭 / (2·1.96). U0와 P1 각각 10개 실행의 평균.
- s_seed(m): 방법 m의 AUC가 시드 10개에서 보인 표준편차.
- 정규성: 시나리오 안에서 표준화한 U0 AUC 190개에 Shapiro–Wilk(기술 목적).

**모의 모형.** 참조 R_1..R_n ~ N(μ, σ_ref²) 독립, 대상 A = μ + Δ + ε_T, ε_T ~ N(0, σ_T²). 규칙은 실제와 같다: se = sqrt(se_boot² + s²/n), s는 모의한 참조의 표본 표준편차, CI = (A − R̄) ± 1.645·se, 통과 ⇔ CI ⊂ (−0.05, 0.05), 기준 초과 ⇔ 통과가 아니고 하한 > 0, 그 외 판정 불가.
- M1(감사 대상 모델 고정): σ_T = 0. Δ는 그 모델과 재학습 기댓값의 차이.
- **M2(주 분석, 방법 수준):** σ_T = σ_ref. 민감도 σ_T ∈ {0.5, 1.5}·σ_ref.
- M3(기록 표집 변동 포함, A2 뒤): d̂에 ε_rec ~ N(0, σ_rec,d²)를 더한다. σ_rec,d는 A2의 대응 부트스트랩에서 얻는다.
- 부트스트랩 반복값은 독립 시드로 쓰지 않는다. se_boot는 규칙이 쓰는 CI 폭의 성분으로만 들어간다.
- 모수: 시나리오별 관측 추정값을 그대로 넣는다. σ_ref의 불확실성은 χ² 90% 하한·상한을 넣은 민감도로 보인다.
- 격자: Δ = −0.10 … 0.15(0.005 간격), n_ref ∈ {2, 3, 4, 5, 10, 20}, 시나리오 19개 전부. 그림은 후기 철회 1/5/10/20%(E2-rate01, E2-base, E2-rate10, E2-rate20)를 대표로 쓰고 나머지는 표로 준다. 칸마다 100,000회, 난수 시드 20261109.

**보고 항목과 판정 기준**
- Q1 동등성 검정력: P(통과 | Δ)를 Δ = 0과 |Δ| = 0.025에서 보고. Δ = 0에서 0.80 이상이면 "검정력 충분", 아니면 "검정력 부족"으로 적는다.
- Q2 거짓 동등 위험: Δ = ±0.05(경계), 0.06, 0.075에서 P(통과 | Δ). 명목 0.05. 0.05 + 3·MC 표준오차 이하이면 "통제됨", 넘으면 "명목 수준 초과"로 적는다. M1·M2·M3 각각.
- Q3 판정 안정성: (모의) 같은 조건을 독립으로 두 번 실행했을 때 같은 분류가 나올 확률. 같은 참조 집합을 공유하는 시드 10개의 통과 수 분포(0/10 … 10/10)와 급내 상관. (관측) 아래 Q4의 부분집합 열거.
- Q4 참조 수 의존성: (모의) n_ref 격자별 Q1·Q2·Q3. (관측) 시나리오마다 U0 모델 10개에서 크기 n = 2…9인 부분집합을 전수 열거해 참조로 쓰고(대상이 U0이면 자기 자신 제외), 방법 P1·U0·U1·U2·U3·U4·U4s의 각 실행을 다시 분류한다. 보고: n별 분류 비율, 보고된 분류와 달라지는 비율. n = 5에서 보고된 분류가 부분집합의 90% 이상에서 유지되면 "안정"으로 적는다. 부분집합은 서로 겹치므로 독립 반복이 아님을 명시한다.
- Q5 양성 대조 민감도: P1형 대상(σ_T = P1의 관측 시드 SD, se_boot = P1의 값)에 대해 P(기준 초과 | Δ). 50%·80% 검출 최소 잔여(MDR50, MDR80)를 시나리오·n_ref별로 보고하고, 관측된 P1 잔여(후기·중기·초기)와 나란히 둔다.
- Q6 모형 적합(관측 대 예측): (a) U0를 대상으로 한 190개 실행은 Δ = 0이 구성상 참이다. 참조를 공유하는 구조(시드 1–5는 참조 중 하나로 n = 4, 시드 6–10은 n = 5)를 그대로 모의해 통과 수의 95% 예측 구간을 만들고 관측 145/190 및 시나리오별 수와 비교한다. 관측이 구간 안이면 "모형 적합", 밖이면 "모형 부적합 — 모의 곡선은 참고용"으로 적는다. (b) P1은 시나리오 평균 차이를 Δ로 넣은 표본 내 비교이므로 기술 목적으로만 쓴다.
- Q7 산술적 가능성: 실행마다 CI 반폭 1.645·se와 δ를 비교해 통과가 불가능한 실행의 비율을 시나리오별로 보고한다(사전 등록 이전 관찰의 확인). 통과가 가능해지는 최소 |X|의 Hanley–McNeil 근사는 "외삽"으로 표시한다.

## 실험 B — C1 원장 동시성

### 정의

- 단위 (k, r): 데이터센터 k가 라운드 r에 올린 입력 커밋(철회 버전 σ, 집합 루트 root_S)과 갱신 커밋.
- W: 정보주체의 `requestWithdrawal`. D: 집계 주체의 수락 `decide(k, r, true, …)`. v_c: 집계 주체가 D를 만들기 전에 읽은 철회 버전.
- 원장 순서: (블록 번호, 거래 색인). v_incl = D보다 원장 순서가 앞선 효력 철회 수.
- **낡은 수락**: D가 성공(UpdateAccepted)했고 v_c < v_incl.
- **부적절한 수락**: 낡은 수락이면서, 그 사이에 효력이 생긴 철회자의 기록이 S_{k,r}에 있다(하네스가 아는 참값).
- **불필요한 되돌림**(v3.2): D가 되돌려졌지만 그 사이 철회자의 기록이 S_{k,r}에 없다.
- 사후 탐지기(이벤트만 읽는 별도 코드):
  - D-pos: WithdrawalEffective와 UpdateAccepted의 (블록, 로그 색인) 순서로 "수락보다 앞선 철회"를 찾고, 그 정보주체의 rid가 커밋된 root_S에 속하는지 비소속 검사를 한다(기존 `fl/evidence.py`의 정렬 머클 구현을 읽기 전용으로 쓴다).
  - D-time: 이벤트의 시각 필드(τ, tEff)만 비교한다.
- δ = 0만 다룬다(실험에 쓴 설정). δ > 0 경로와 공개된 네 가지 잔존 공백은 범위 밖이며 해결된 것으로 표시하지 않는다.
- 컨트랙트 소스는 고치지 않는다. `contracts/ConsentLedger.sol`(v3.1)과 `contracts/ConsentLedger_v3_2.sol`을 `tools/bin/solc`(0.8.38, `--evm-version prague --optimize`)로 그대로 컴파일하고 바이트코드 해시를 기록한다. 수정이 필요해 보이는 점은 별도 변경안으로만 적는다.

### 사전 가설(틀리면 그대로 보고)

- H-B1(v3.1): W가 D보다 원장 순서가 앞서고 v_c가 W 이전 값이면 D는 성공한다(낡은 수락). 이벤트의 `withdrawalVersion`은 포함 시점의 효력 철회 수와 같다. D-pos는 부적절한 수락을 전부 찾고, 잘못 찾는 것은 없다.
- H-B2(v3.2): 모든 조건에서 낡은 수락은 0건이다. v_c가 실행 시점 버전과 다른 D는 "stale version"으로 되돌려진다. W는 전부 반영된다.
- H-B3(두 버전): D가 W보다 원장 순서가 앞서면(같은 블록 포함) D는 성공하고 D-pos는 찾지 않는다.
- H-B4: 같은 블록에서 D가 먼저인 경우 시각만 보는 D-time은 이를 위반으로 잘못 찾는다.
- H-B5(v3.2의 비용): 조회와 포함 사이에 무관한 철회(다른 기관)가 끼면 D는 되돌려진다(불필요한 되돌림). 버전을 다시 읽어 한 번 재제출하면, 그 사이 새 철회가 없을 때 성공한다.

### B-L 로컬 EVM(순서를 통제)

- 환경: `release/requirements-test.txt` 고정판(web3 8.0.0, eth-tester 0.14.0b1, py-evm 0.12.1b1)의 새 가상환경. 자동 채굴을 끄고 블록·블록 안 순서를 하네스가 정한다.
- 조건(버전 2 × 철회자 소속 {같은 기관, 다른 기관}마다):
  - L1 철회 확정 뒤 수락: W 채굴 → 새로 조회 → 정직한 후속(같은 기관이면 거절, 다른 기관이면 새 v_c로 수락).
  - L2 수락 확정 뒤 철회: D 채굴 → W 채굴.
  - L3 거의 동시 제출: 둘 다 대기 상태에서, 같은 블록/이웃 블록과 순서를 무작위로 정한다.
  - L4 제출 순서 ≠ 포함 순서: 서명·제출 순서와 반대로 포함시킨다(같은 블록, 이웃 블록).
  - L5 같은 블록: W→D, D→W 두 순서.
  - L6 지연된 조회: v_c를 L ∈ {1, 2, 5}블록 전 상태에서 읽고, 그 사이에 W가 K ∈ {1, 2, 3}건 포함된다.
- 칸마다 50회, 무작위 요소(선행 철회 수, 라운드, 지연, K, 블록 간격)는 시드 20261109로 미리 뽑는다.
- 2차(비용): v3.2에서 블록마다 무관한 철회가 확률 q ∈ {0.1, 0.5, 0.9}로 도착하고 조회가 1블록 늦을 때, 수락까지의 제출 횟수(상한 20).
- 재현: 전체를 같은 시드로 3회 실행해 결과 벡터의 해시가 같은지 본다(재현 성공률).
- 지표: 낡은 수락·부적절한 수락 건수, 철회 반영률, D-pos·D-time의 탐지와 오탐, 포함 순서별 판정, 가스, 되돌림과 불필요한 되돌림, 재제출 횟수.

### B-T Kairos 테스트넷(관측)

- 새로 배포: v3.1 1개, v3.2 1개(δ = 0, 데이터센터 3, 기존 실험과 같은 역할 계정, 플랫폼 수수료 대납). 배포된 코드가 로컬 컴파일 결과와 같은지 `eth_getCode`로 확인한다.
- 환경: 기존 원장 컨테이너 이미지 `dissertation-ledger:0.5`(web3py-ext 2.1.0)에서 새 하네스를 실행한다. 키 디렉터리는 읽기 전용으로 연결하고 키 값을 출력·기록하지 않는다. `ledger/`는 고치지 않는다.
- 버전당 150회. 시행마다 독립된 두 제출자(별도 연결·스레드)가 W와 D를 낸다. 제출 시각 차 o_D − o_W ~ U(−1.5 s, +1.5 s)를 시드 20261109로 미리 뽑는다. 철회자가 단위 k 소속일 확률 0.5. v_c는 D 제출 전에 "latest"로 읽는다(실험 서비스의 블록 고정 조회와 구분해 기록).
- 포함 순서는 통제하지 않는다. 영수증의 (블록, 거래 색인)으로 사후에 {W 먼저·다른 블록, W 먼저·같은 블록, D 먼저·같은 블록, D 먼저·다른 블록}으로 나눈다. 관측되지 않은 부류는 "테스트넷에서 관측되지 않음"으로 적고 만들어 내지 않는다.
- v3.2에서 되돌려진 D에는 정직한 후속(영수증 블록에 고정해 다시 읽고, 같은 기관이면 거절·다른 기관이면 재수락)을 하고 제출 횟수를 잰다.
- 지연된 조회: W 영수증 직후 "latest" 조회를 독립 연결 3개로 하고, W 이전 값이 돌아온 비율을 잰다.
- 지표: B-L과 같고, 추가로 제출→영수증 지연(초, 블록), 수수료, 제출 순서와 포함 순서가 뒤바뀐 비율.
- 제외 규칙: RPC 오류·시간 초과로 두 영수증을 얻지 못한 시행은 사유와 함께 제외로 기록한다. 제외분을 채우려고 시행을 추가하지 않는다.
- 예산: 누적 수수료가 10 KAIA를 넘으면 중단한다.
- 보고에서 v3.2의 로컬 결과와 테스트넷 결과를 따로 적는다.

### B의 한계(미리 적어 둠)

- 로컬 EVM의 순서는 하네스가 강제한 것이라 실제 네트워크의 순서 분포를 나타내지 않는다.
- 테스트넷 관측은 한 시기, 한 공개 RPC, 제출자 2명이다. 블록 제안자의 순서 정책과 다수 제출자 부하는 다루지 않는다.
- 부적절한 수락의 참값(기록 소속)은 하네스가 정한다.
- v3.2를 테스트넷에서 실행해도 E1–E4가 v3.1로 수행됐다는 사실은 바뀌지 않는다.
